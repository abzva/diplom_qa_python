## Общие условия и данные

- Стенд: `https://automationexercise.com`. Перед каждым кейсом — отдельный чистый профиль/изолированная браузерная сессия, без расширений, меняющих страницу. Для MAN-04 не менять сессию между добавлением и входом.
- Дождаться видимого результата каждого действия. Если вместо страницы возникла сетевая ошибка или действие перекрыто рекламой, сохранить URL, время и снимок без секретов; зафиксировать невыполненные шаги. Не засчитывать их по предположению и не обходить проверяемый переход прямым URL.
- Товары выбирать из текущей выдачи; записывать название и ссылку карточки (ID — число в `/product_details/<ID>`), при необходимости цену. Не закреплять порядок, число товаров в каталоге или конкретную цену. Дубликат при наведении не считать отдельным товаром.
- Не оформлять заказ, не оплачивать, не отправлять Contact us, подписки, письма или отзывы. MAN-04/05 работают только с отдельным собственным тестовым аккаунтом.

**Подготовка аккаунта для MAN-04 и MAN-05:** для каждого кейса нужен свой новый одноразовый аккаунт, ранее не использовавшийся для покупок или корзины. Подготовить его отдельно через документированный `POST /api/createAccount`, form-поля по [API 11](https://automationexercise.com/api_list). Состав полей и безопасные вымышленные адресные данные есть в [CreateAccountRequest](../models/account.py). Имя — `Manual <уникальная метка>`, email — `manual_<уникальная метка>@example.test`, пароль — новый случайный, хранится только локально. Не использовать реальные контакты и не запускать pytest ради подготовки: его фикстура удалит аккаунт. Ожидаемые HTTP 200 и бизнес-код 201 при создании ранее наблюдались в проекте, это разные значения; готовность реквизитов подтверждается verifyLogin. Если аккаунт не подготовлен, предусловие не выполнено; шаги входа не считать проверенными. В кейс и вложения TestOps переносить обозначения данных, а не пароль.

**Очистка собственного аккаунта:** после MAN-04/05 использовать только сохранённые исходные email/пароль этого кейса. `POST /api/verifyLogin` с form-полями email/password: ожидаем HTTP 200 и JSON с бизнес-кодом 200 и сообщением существования пользователя; затем `DELETE /api/deleteAccount` с теми же полями — HTTP 200 и бизнес-код 200 с подтверждением удаления. Повторный verifyLogin должен дать HTTP 200, `responseCode=404`, `message="User not found!"`. Если отсутствие уже подтверждено этим ответом, повторный DELETE не нужен. Сетевая ошибка, иной ответ или ошибка JSON не подтверждают очистку: сохранить безопасную диагностику и отметить незавершённую очистку. Порядок реализован в [фикстуре account_data](../tests/conftest.py) с [API-проверкой реквизитов](../diplom_qa_python/api/accounts.py). Не удалять общий/чужой аккаунт. После очистки закрыть изолированную сессию.
